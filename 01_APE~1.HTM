Concepto

¿Qué es React, exactamente?

Hasta hoy usamos React de forma indirecta — Vite lo instaló, pero todo lo que escribimos (navbar, tarjetas, footer) fue HTML con clases Tailwind. React es la librería que construye ese HTML de forma dinámica, a partir de código JavaScript.

📚
Una librería, no un lenguaje
React es JavaScript — no es un lenguaje nuevo. Es un conjunto de herramientas para construir interfaces sin escribir manualmente document.createElement() una y otra vez.
🧩
Todo se arma con componentes
En vez de un solo HTML gigante, la interfaz se divide en piezas pequeñas y reutilizables — cada una es un componente.
🔄
Actualiza solo lo que cambia
Cuando algo cambia en pantalla (ej. un contador), React no recarga toda la página — actualiza solo esa parte. Esto se explica en el siguiente slide (Virtual DOM).
✅ Lo que ya sabíamos, con otro nombre
function App() { return (...) } ya es un componente de React — lo escribimos desde S19 sin llamarlo así todavía. Hoy le ponemos nombre a lo que ya veníamos haciendo, y aprendemos a crear un segundo.
💡 ¿Hay que instalar React hoy?
No — ya está instalado desde S19. Cuando corrimos npm create vite@latest frontend-react -- --template react, esa plantilla --template react ya agregó React como dependencia en package.json, junto con Vite. Por eso App.jsx ya era un componente de React desde el primer día — solo lo usábamos únicamente para escribir HTML con clases Tailwind, sin aprovechar nada más. Hoy es la primera vez que usamos React de verdad.

Recordando S05

El patrón que ya usamos... y su costo oculto

En la Sesión 5 (Fase 2, JavaScript y el DOM) construimos el buscador de productos con este patrón — reemplazar TODO el contenido cada vez que algo cambia:

S05 — main.js (código real que ya escribiste)
1// Cada vez que el usuario escribe en el buscador...
2const gridTarjetas = document.querySelector('#grid-tarjetas');
3
4gridTarjetas.innerHTML = productos.map(crearTarjeta).join('');
❌ Lo que realmente pasa en esa línea 4
Aunque solo cambie el texto de una tarjeta (ej. el usuario filtra y quedan 5 de 6), .innerHTML = borra las 6 tarjetas completas del DOM real y las vuelve a crear desde cero — imágenes, botones, textos, todo. El navegador tiene que recalcular estilos y volver a pintar las 6, no solo la 1 que cambió.
🔴 Simulación — cada vez que escribes en el buscador de S05
Las 6 tarjetas parpadean todas — se destruyen y se vuelven a crear, aunque solo 1 tuviera que cambiar.
⚠️ Esto no estuvo "mal" en S05
Para 6 tarjetas es imperceptible — por eso funcionaba perfecto. El problema aparece cuando la interfaz crece: cientos de elementos, actualizaciones frecuentes (un contador, un chat, un formulario con validación en vivo). Ahí ese "recrear todo" sí se nota, y es exactamente el problema que resuelve el Virtual DOM.

Concepto

Virtual DOM — la idea, no la implementación

No vamos a programar el Virtual DOM — React lo hace por nosotros. Pero entender la idea explica por qué React resuelve el problema del slide anterior.

🟢 El mismo cambio, pero con React
Solo la tarjeta que realmente cambió se actualiza — las otras 5 ni se tocan.
❌ Patrón de S05
innerHTML = reemplaza TODO el contenido del contenedor — no hay forma de decirle "solo cambia esta parte".
VS
✅ Con Virtual DOM (React)
React mantiene una copia ligera del DOM en memoria. Cuando algo cambia, compara la copia vieja con la nueva, calcula la diferencia mínima, y solo actualiza esa parte en el DOM real.
💡 Analogía simple
Es como editar un documento: en vez de reimprimir todo el documento cada vez que cambias una palabra, solo corriges esa palabra en la hoja ya impresa. El Virtual DOM es el "borrador" donde React calcula qué cambió antes de tocar la página real.
⚠️ No se programa manualmente
El Virtual DOM es interno de React — nunca vamos a escribir código que lo maneje directamente, ni un querySelector como en S05. Solo hace falta entender que existe y por qué React puede actualizar la pantalla sin recargar la página completa.

JSX — HTML dentro de JavaScript

Ya venimos escribiendo JSX desde S19 sin saber su nombre — es la sintaxis que mezcla HTML con JavaScript dentro de un componente.

Esto que ya escribimos ES JSX
1function App() {
2return (
3 <nav className="flex ...">
4 TechStore Pro
5 </nav>
6)
7}
Regla de JSXPor qué
Un único elemento raíz por returnPor eso S19 usó <>...</> — JSX no permite devolver dos elementos sueltos
className en vez de classclass es palabra reservada en JavaScript — JSX usa el nombre de la propiedad real del DOM
Etiquetas siempre se cierran<img />, no <img> — a diferencia del HTML normal
{ } para JavaScript dentro del HTMLCualquier variable o expresión se escribe entre llaves — lo usaremos desde S22 en adelante
08 / 14
Concepto

Un componente es una función que devuelve JSX

Esa es toda la definición. Un componente de React no es más que una función de JavaScript normal, con dos reglas simples.

🔠
Empieza con mayúscula
function Navbar(), no function navbar() — así React distingue un componente de una etiqueta HTML normal.
↩️
Devuelve JSX
Su return siempre entrega HTML mezclado con JavaScript — nunca un número o texto suelto.
Hoy — todo en un archivo
App.jsx contiene el navbar, el catálogo y el footer, todos mezclados en el mismo return.
Después de hoy — separado
Navbar.jsx vive en su propio archivo. App.jsx lo importa y lo usa como <Navbar />.
✅ La idea clave de hoy
Un componente se usa dentro de otro escribiéndolo como si fuera una etiqueta HTML: <Navbar />. React lo reconoce como componente (no como HTML) porque empieza con mayúscula — es la misma regla del slide anterior.
